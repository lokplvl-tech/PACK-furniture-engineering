## [FE.M.007] Фотореалистичная визуализация изделия для клиента

### Definition

Метод превращения готовой (прошедшей гейт Технолога, FE.M.001 позиция 8) CAD-модели мебельного изделия в фотореалистичное изображение для показа клиенту - без изменения геометрии/деталей модели. Два равноправных пути в зависимости от роли и задачи, не «либо-либо» раз и навсегда.

### Purpose

Клиент принимает решение о заказе легче, когда видит реалистичный образ будущего изделия, а не чертёж или предварительный 3D-каркас. Метод формализует, как получить такое изображение надёжно (без риска незаметно исказить пропорции или состав изделия) и с учётом того, кто именно его выполняет - дизайнер на конкретной сделке или автоматический сервис для множества клиентов сайта.

### Forces

| Force | Tension |
|-------|---------|
| Точность деталей vs скорость/массовость | Рендер внутри самой CAD-программы (Путь А) даёт стопроцентную гарантию, что изображена именно спроектированная модель - но требует запуска десктопной программы на каждый рендер, не годится как безлюдный веб-сервис для множества посетителей сайта одновременно (Путь Б через ИИ-генерацию с картой глубины - см. `04-work-products/FE.WP.003.md` - подходит для этого, но менее строго держит форму) |
| Единый инструмент vs межплатформенная совместимость | Рендер прямо в Базис - меньше шагов, ничего никуда не переносится; но если модель нужно показать в другом инструменте (SketchUp, Unreal Engine для сайта) - обязателен явный шаг экспорта, который сам по себе может потерять часть материалов/масштаб, если сделан небрежно |

### Inputs

| Input | Description | Required? |
|-------|-------------|-----------|
| Готовая CAD-модель изделия | Прошла гейт Технолога (FE.M.001 позиция 8) - визуализировать непроверенную модель бессмысленно, придётся переделывать | Yes |
| Текстуры материалов (диффузная/альбедо, шероховатость/глянец, рельеф/нормали) | Три карты на материал - без них рендер выглядит плоским или пластиковым, независимо от движка | Yes |
| Целевой инструмент рендера | Базис (встроенные V-Ray/Cycles) или внешний движок (Unreal Engine/Blender/SketchUp) через OBJ | Yes |

### Key Distinctions

- [FE.D.009: Рендер vs Генерация](../01-domain-contract/01B-distinctions.md#fe-d-009) - Путь А (В-Рэй/Циклес) отрисовывает ту же модель по её реальной геометрии, гарантированная точность. Генерация с картой глубины дорисовывает изображение по модели-подсказке - высокая, но не стопроцентная точность. Путать нельзя - для гарантийного показа клиенту на сделке годится только Путь А.

### Tools Commonly Used

| Tool | How Used |
|------|----------|
| Базис-Мебельщик (встроенные рендереры V-RAY и Cycles) | Путь А - рендер без выхода из программы, материалы настраиваются тремя картами (альбедо/шероховатость/рельеф), свет - несколько точечных/направленных источников для мягких теней |
| Экспорт в формат OBJ | Мост между Базис и внешними движками (Unreal Engine, Blender, SketchUp) - при переносе нужен поворот осей координат под целевой движок, иначе модель окажется на боку |

### SoTA Status

**Status**: `current`

**Basis**: встроенные рендереры В-Рэй и Циклес и экспорт в OBJ - подтверждённая функция самого Базис-Мебельщик (не предположение), проверено по независимому источнику ([sapr.ru](https://sapr.ru/article/26817), [bazis-center.ru](https://bazis-center.ru/system/mebelschik)). Для PRO100 и SketchUp путь Б (универсальный 3D-формат) применим по аналогии - экспорт в OBJ/подобные форматы стандартен для CAD этого класса, но конкретные шаги для этих двух программ отдельно не проверены, только предположены по общей логике формата.

**Revision criterion**: если для PRO100 или SketchUp находится задокументированный собственный путь (например, свой встроенный рендер) - добавить отдельной строкой, не смешивать с путём Б.

## Алгоритм воспроизводства (шаг за шагом, DRAKON-схема - основной артефакт)

**Схема ДРАКОН ещё не построена - честно, не выдумываю ссылку на несуществующий файл.** По конвенции этого пака (см. `07-map/FE.M.001.drakon-spec.md`, метод `DRK.M.001`) схема должна пройти девять формальных позиций нарративизации, не быть просто перечнем шагов - это отдельная работа, следующий шаг. Текст ниже - только пронумерованный алгоритм, черновая основа для будущей схемы, не сама схема.

1. Проверить, что модель прошла гейт Технолога (FE.M.001, позиция 8) - иначе не начинать.
2. Развилка по инструменту: модель в Базис-Мебельщик и рендер нужен там же → Путь А. Модель нужно показать в другой программе (SketchUp/Unreal Engine/веб-сервис) → Путь Б.
3. **Путь А (в самом Базис):** выбрать встроенный рендерер (V-Ray или Cycles) → настроить три карты материала на каждую поверхность (альбедо, шероховатость, рельеф) → расставить несколько точечных/направленных источников света для мягких теней и бликов → запустить рендер.
4. **Путь Б (внешний движок):** экспортировать сцену в формат OBJ → импортировать в целевую программу (повернуть оси координат, если модель легла на бок) → настроить материалы и свет по требованиям целевой программы → запустить рендер там.
5. Сверить итоговое изображение с исходной моделью - геометрия и состав изделия не должны отличаться от того, что спроектировано.
